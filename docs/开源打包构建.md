## 1. 发布产物与渠道

| 平台 | 产物 | 构建工具 | 签名 | 分发渠道 |
|---|---|---|---|---|
| Windows | `Vidly-Setup-<ver>.exe` | Inno Setup 6 | SignPath（免费，开源计划） | GitHub Release |
| macOS | `Vidly-<ver>.dmg` | hdiutil | Developer ID + Apple 公证（自有账号） | GitHub Release |
| Linux | `vidly_<ver>_amd64.deb` | dpkg-deb | 无（Linux 无签名惯例） | GitHub Release |
**为什么砍掉便携版 / AppImage / 单文件嵌入**：
- 安装包形态统一了“安装、卸载、快捷方式、开始菜单/启动台/应用列表”体验，减少维护面
- ffmpeg 以独立文件随包分发（方式 A），`find_ffmpeg` 已优先扫描主程序同目录，**零代码改动**即可工作
- 之前实现的 `bundle` 单文件嵌入 feature 保留在代码里但不启用（安装包场景无必要，且自解压模式会显著抬高杀软误报率）
- AppImage 需要额外维护 linuxdeploy 流程；deb 覆盖 Ubuntu/Debian 系已满足绝大多数目标用户
**版本号唯一来源**：`Cargo.toml` 的 `version` 字段（3 段 semver）。Inno、Info.plist、deb control、Release tag 全部由 CI 从这里读取，禁止手写各处版本。**Windows / Microsoft Store 需要 4 段版本**，CI 在 Windows job 里派生 `VER4=<version>.0`（如 `0.1.0` → `0.1.0.0`）供 Inno/Store 使用；macOS/Linux 仍用 3 段。

## 2. 开源许可证

> ⚠️ **顺序提醒**：必须先定下许可证再申请 SignPath 免费签名——其申请条件之一就是“公开仓库 + OSI 认证的开源协议”。

### 2.1 应用本体：推荐 MIT

| 协议 | 特点 | 适合度 |
|---|---|---|
| **MIT** ✅ 推荐 | 一页纸、无 copyleft、社区认知度最高 | GUI 小工具的最常见选择 |
| Apache-2.0 | 多了显式专利授权，企业贡献者更安心 | 备选（与 MIT 依赖全兼容） |
| GPL-3.0 | 强 copyleft，衍生作品必须开源 | 只有当你希望“ forks 也必须开源”时选 |
| MPL-2.0 | 文件级弱 copyleft | 无必要 |
**推荐 MIT 的理由**：
1. 本项目所有关键依赖均为宽松协议或弱协议：iced（MIT/Apache-2.0）、tokio（MIT）、serde（MIT/Apache-2.0）、thiserror（MIT/Apache-2.0）、opener（MIT）、rfd（**MPL-2.0**，文件级弱 copyleft——对开源仓库无任何额外负担，见 2.3）
2. 应用通过**子进程**调用 ffmpeg（不是链接 libav*），属于“聚合分发”，应用本体协议**不会**被 ffmpeg 的 LGPL 传染
3. MIT 与后续想做的任何分发方式（含商店上架）都不冲突

### 2.2 与 FFmpeg（LGPL）的合规义务

分发内含 ffmpeg 的安装包，LGPL 要求做到以下几点：
| # | 义务 | 本项目落地点 |
|---|---|---|
| 1 | **必须使用 LGPL 构建**（不能是 GPL/非自由构建） | 三平台统一用 `scripts/build-ffmpeg-min.sh` 自建极简构建（`--disable-gpl --disable-nonfree`，只编 remux 所需组件，约 8–12 MB/平台） |
| 2 | 附 FFmpeg 许可证与版权文本 | 自建版为 **LGPL v2.1+**：脚本把源码里的 `COPYING.LGPLv2.1` 复制为 `out/bin/LICENSE-ffmpeg.txt`，各包内附（安装包 `dist/LICENSE-ffmpeg.txt`、deb `/usr/share/doc/vidly/`、macOS `.app/Contents/Resources/`）。仓库根 `LICENSE-ffmpeg.txt` 同为 v2.1 |
| 3 | 提供所用 ffmpeg 源码的获取途径 | 关于页与 README 放 `https://ffmpeg.org/releases/` 链接；自建脚本与版本号见 `scripts/build-ffmpeg-min.sh`（`FFMPEG_VER`） |
| 4 | 声明使用了 FFmpeg | 关于页 + README 固定文案（见附录 12.4） |
| 5 | 允许用户替换 ffmpeg | 天然满足：用户可直接覆盖安装目录中的 `ffmpeg(.exe)`；程序探测顺序为「exe 同目录 → deb 目录 → PATH → 常见目录」，覆盖即生效 |

### 2.3 依赖合规速查

| 依赖 | 协议 | 开源仓库下的义务 |
|---|---|---|
| iced / tokio / serde / thiserror / opener / tracing | MIT / Apache-2.0 | 无（在 THIRD_PARTY.md 列出即可） |
| **rfd** | **MPL-2.0** | 需提供对应版本源码获取途径 → THIRD_PARTY.md 中放 crates.io/仓库链接即满足 |

### 2.4 需要落地的文件

```
仓库根目录/
├── LICENSE              # MIT（Copyright (c) 2026 <你的名字>）
├── LICENSE-ffmpeg.txt   # COPYING.LGPLv2.1（三平台自建版一致）
├── THIRD_PARTY.md       # 依赖清单（模板见附录 12.2）
└── README.md            # 含 "uses FFmpeg under LGPL" 声明（附录 12.3）
# 注意：macOS 自建版为 LGPL v2.1+，其 COPYING.LGPLv2.1 随 .app 打包，不用根目录这份。
```

## 3. 打包材料准备

### 3.1 ffmpeg（LGPL）获取对照表

| 平台 | 来源 | 许可 | 备注 |
|---|---|---|---|
| Windows | 自建（`scripts/build-ffmpeg-min.sh`，MSYS2/MINGW64） | LGPL v2.1+ | CI 用 `msys2/setup-msys2` 装 `gcc/make/nasm/xz` 后跑脚本；约 8–12 MB |
| Linux | 自建（同上，本机编译） | LGPL v2.1+ | `apt install nasm` 后跑脚本 |
| macOS | 自建（同上） | LGPL v2.1+ | `brew install nasm` 后跑脚本 |
> 三平台统一极简自建（只编 remux 所需 demuxer/muxer/bsf），安装包体积约 40 MB。若想更省事也可临时换回 BtbN 预编译（注意其 `-lgpl` 实为 LGPL v3，许可证文本要随之更换）。

### 3.2 应用图标三件套

从一张 1024×1024 PNG（`assets/icon.png`）生成：
```bash
# Windows .ico
magick assets/icon.png -define icon:auto-resize=256,128,64,48,32,16 assets/vidly.ico
# macOS .icns（在 mac 上执行）
mkdir icon.iconset
for s in 16 32 128 256 512; do
  magick assets/icon.png -resize ${s}x${s}   icon.iconset/icon_${s}x${s}.png
  magick assets/icon.png -resize $((s*2))x$((s*2)) icon.iconset/icon_${s}x${s}@2x.png
done
iconutil -c icns icon.iconset -o assets/vidly.icns
# Linux
magick assets/icon.png -resize 256x256 assets/vidly-256.png
```

### 3.3 Windows exe 嵌图标

**Cargo.toml**：
```toml
[build-dependencies]
winresource = "0.1"
```
**build.rs**（仓库根，新增）：
```rust
fn main() {
    // 用 CARGO_CFG_TARGET_OS 而非 cfg!，交叉编译时也正确
    if std::env::var("CARGO_CFG_TARGET_OS").unwrap_or_default() == "windows" {
        let mut res = winresource::WindowsResource::new();
        res.set_icon("assets/vidly.ico");
        res.set("FileDescription", "Vidly");
        res.compile().expect("failed to embed windows resources");
    }
    println!("cargo:rerun-if-changed=assets/vidly.ico");
}
```

## 5. Windows：Inno Setup 安装包

### installer.iss

```ini
; 用法：ISCC /DVersion=x.y.z installer.iss
; 产物：Output/Vidly-Setup-x.y.z.exe
#ifndef Version
  #define Version "0.0.0"
#endif
[Setup]
AppId={{3F9C1A54-7B2E-4D86-9A17-C05E4412B780}}   ; 生成一次后永远别改（升级识别靠它）
AppName=Vidly
AppVersion={#Version}
AppPublisher=YourName
AppPublisherURL=https://github.com/you/vidly
DefaultDirName={autopf}\Vidly
PrivilegesRequired=lowest          ; 装到用户目录，无需 UAC，卸载也更干净
OutputBaseFilename=Vidly-Setup-{#Version}
SetupIconFile=assets\vidly.ico
UninstallDisplayIcon={app}\vidly.exe
Compression=lzma2/max
SolidCompression=yes
WizardStyle=modern
ArchitecturesInstallIn64BitMode=x64compatible
[Files]
Source: "dist\vidly.exe";          DestDir: "{app}"; Flags: ignoreversion
Source: "dist\ffmpeg.exe";         DestDir: "{app}"; Flags: ignoreversion; Check: NeedsFfmpeg
Source: "dist\ffprobe.exe";        DestDir: "{app}"; Flags: ignoreversion; Check: NeedsFfmpeg
Source: "dist\LICENSE-ffmpeg.txt"; DestDir: "{app}"; Flags: ignoreversion; Check: NeedsFfmpeg
[Tasks]
Name: "desktopicon"; Description: "创建桌面快捷方式"; Flags: unchecked
[Icons]
Name: "{autoprograms}\Vidly"; Filename: "{app}\vidly.exe"
Name: "{autodesktop}\Vidly";  Filename: "{app}\vidly.exe"; Tasks: desktopicon
[Run]
Filename: "{app}\vidly.exe"; Description: "立即运行"; Flags: nowait postinstall skipifsilent
[Code]
// 仅当目标机 PATH 上没有 ffmpeg + ffprobe 时，才安装内置的 LGPL FFmpeg；
// 系统已有则跳过（Vidly 的探测顺序：exe 同目录 → PATH → 常见目录）。
function OnPath(const Exe: String): Boolean;
var ResultCode: Integer;
begin
  Result := Exec('where.exe', Exe, '', SW_HIDE, ewWaitUntilTerminated, ResultCode)
    and (ResultCode = 0);
end;
function NeedsFfmpeg(): Boolean;
begin
  Result := not (OnPath('ffmpeg.exe') and OnPath('ffprobe.exe'));
end;
procedure CurStepChanged(CurStep: TSetupStep);
begin
  if (CurStep = ssPostInstall) and (not NeedsFfmpeg()) and (not WizardSilent) then
    MsgBox('检测到系统已安装 FFmpeg，已跳过内置版本。', mbInformation, MB_OK);
end;
```
> exe 安装包本身不嵌应用图标资源也没关系——`SetupIconFile` 决定安装包图标，`build.rs` 决定安装后 exe 的图标。

## 6. Windows：免费代码签名

### 6.1 先讲清楚现实（重要）

| 方案 | 费用 | SmartScreen 效果 | 结论 |
|---|---|---|---|
| **SignPath 开源计划** ✅ | **免费** | 标准 证书，信誉需积累（初期仍可能提示） | 开源项目的**唯一真免费正规方案** |
| Certum OSS 证书 | 约 €25–30/年 | 同上 | 便宜备选（个人可申请） |
| 自签名 | 免费 | ❌ 无任何公信力，等于没签 | 只用于本地测试 |
| EV 证书 / Azure Trusted Signing | 数百 €/年 或 $9.99/月 | ✅ 签名即过 | 需企业身份验证，不适合个人开源 |
背景：2023 年 6 月起 CA/B Forum 强制代码签名私钥硬件隔离，市场上的廉价个人证书基本消失。SignPath 以“私钥托管在其 HSM + 网页审批 + CI 集成”的方式满足规范，并向合格开源项目**免费**提供签名服务（SignPath Foundation 运营）。

### 6.2 申请 SignPath 开源计划（一次性，约 1–2 周审核）

**申请条件**（我们全部满足）：
- ✅ 公开的 GitHub 仓库
- ✅ OSI 认证协议（第 2 节已选 MIT，先把 LICENSE 提交上去）
- ✅ 非商业用途
- ✅ 有基本可用的 README
**步骤**：
1. 访问 SignPath 官网（`signpath.org`），进入 **Open Source / Foundation** 计划页提交申请：仓库地址、项目简介、联系方式
2. 审核通过后，按引导创建组织 → 在 GitHub 安装 **SignPath GitHub App** 并授权本仓库
3. 在 SignPath 控制台：
   - 创建项目 `vidly`
   - 使用其签发的代码签名证书
   - 创建 **Signing Policy**（如 `release-signing`），建议限制为 `main` 分支与 `v*` tag 触发
   - 创建 **Artifact Configuration**：定义“上传的 zip 中所有 `*.exe` 逐一签名”
4. 在 GitHub 仓库 Secrets 中添加：
   | Secret | 内容 |
   |---|---|
   | `SIGNPATH_API_TOKEN` | SignPath 控制台生成的 API Token |
   | `SIGNPATH_ORG_ID` | 组织 ID（控制台可见） |

### 6.3 CI 中的签名集成（两段式）

流程：**编译产物打包 → 送 SignPath 签名 → 解包 → Inno 打安装包 → 安装包再签一次**：
```
vidly.exe + ffmpeg.exe + ffprobe.exe
        │ 打成 unsigned.zip
        ▼
   SignPath 签名（action）──► signed.zip ──► 解回 dist/
        ▼
   ISCC 打包 ──► Vidly-Setup.exe
        ▼
   SignPath 签名 ──► 上传 Release
```
具体 YAML 见第 9 节。⚠️ SignPath 官方 action（`SignPath/github-action-signpath-action`）的参数名随版本略有调整，使用时以其 README 为准，第 9 节中的写法标注了需要核对的参数。
> **过渡期策略**：申请审核期间可以先用无签名版本发布，用户首次运行会看到 SmartScreen 蓝色警告（“更多信息 → 仍要运行”）。拿到签名后重新发一版即可，且签名版的 SmartScreen 信誉会随下载量逐步积累。

## 7. macOS：签名与公证

> 你已有 Apple Developer 账号，本节是完整操作手册。公证是硬要求：macOS Gatekeeper 会直接拦截未公证的 Developer ID 应用。

### 7.1 前置准备（一次性）

1. **证书**：Xcode /Certificates 里创建 **Developer ID Application** 证书，导出 `.p12`，base64 后存入 GitHub Secret `MACOS_P12_B64`，密码存 `MACOS_P12_PASSWORD`
2. **公证凭据（App Store Connect API Key，最适合 CI）**：appstoreconnect.apple.com → Users and Access → Integrations → 新建 Team Key，获得：
   - Key ID → `APPLE_API_KEY_ID`
   - Issuer ID → `APPLE_API_ISSUER`
   - 下载的 `.p8` 文件 base64 → `APPLE_API_KEY_B64`
3. 签名身份字符串（形如 `Developer ID Application: YOUR NAME (AB12CD34EF)`）→ `MACOS_SIGN_IDENTITY`

### 7.2 scripts/package-macos.sh（打包 + 签名 + 公证 + DMG，全文）

```bash
#!/usr/bin/env bash
# 用法：./scripts/package-macos.sh <version>
# 前置：target/release/vidly 与 out/bin/{ffmpeg,ffprobe} 已就绪
set -euo pipefail
VER="${1:?usage: package-macos.sh <version>}"
SIGN_IDENTITY="${MACOS_SIGN_IDENTITY:?need MACOS_SIGN_IDENTITY}"
APP="dist/Vidly.app"
mkdir -p "$APP/Contents/MacOS" "$APP/Contents/Resources" dist
cp target/release/vidly out/bin/ffmpeg out/bin/ffprobe "$APP/Contents/MacOS/"
cp assets/vidly.icns "$APP/Contents/Resources/"
cp out/bin/LICENSE-ffmpeg.txt "$APP/Contents/Resources/"   # 自建版 LGPL v2.1+ 文本
cat > "$APP/Contents/Info.plist" <<EOF
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>CFBundleName</key><string>Vidly</string>
  <key>CFBundleDisplayName</key><string>Vidly</string>
  <key>CFBundleIdentifier</key><string>com.yourname.vidly</string>
  <key>CFBundleExecutable</key><string>vidly</string>
  <key>CFBundlePackageType</key><string>APPL</string>
  <key>CFBundleIconFile</key><string>vidly</string>
  <key>CFBundleShortVersionString</key><string>${VER}</string>
  <key>CFBundleVersion</key><string>${VER}</string>
  <key>LSMinimumSystemVersion</key><string>11.0</string>
  <key>NSHighResolutionCapable</key><true/>
</dict>
</plist>
EOF
# ── 1. 签名（顺序关键：先嵌套二进制，后 .app 整体）──────────────────
for bin in ffmpeg ffprobe; do
  codesign --force --timestamp --options runtime \
    --sign "$SIGN_IDENTITY" "$APP/Contents/MacOS/$bin"
done
codesign --force --timestamp --options runtime \
  --sign "$SIGN_IDENTITY" "$APP"
codesign --verify --deep --strict "$APP"
# ── 2. DMG ──────────────────────────────────────────────────────────
hdiutil create -volname "Vidly" -srcfolder "$APP" -ov -format UDZO \
  "dist/Vidly-${VER}.dmg"
# ── 3. 公证 + 装订（CI 中由调用方准备 p8，这里只做提交）──────────────
if [[ -n "${APPLE_API_KEY_ID:-}" && -n "${APPLE_API_KEY_B64:-}" ]]; then
  KEY_PATH="$HOME/private_keys/AuthKey_${APPLE_API_KEY_ID}.p8"
  mkdir -p "$HOME/private_keys"
  echo -n "$APPLE_API_KEY_B64" | base64 --decode > "$KEY_PATH"
  xcrun notarytool submit "dist/Vidly-${VER}.dmg" \
    --key "$KEY_PATH" \
    --key-id "$APPLE_API_KEY_ID" \
    --issuer "$APPLE_API_ISSUER" \
    --wait
  xcrun stapler staple "dist/Vidly-${VER}.dmg"
  xcrun stapler validate  "dist/Vidly-${VER}.dmg"
fi
echo "✅ dist/Vidly-${VER}.dmg（已签名并公证）"
```

### 7.3 公证高频失败原因

| 报错 | 原因 |
|---|---|
| `The binary is not signed with a valid Developer ID certificate` | **忘了先签 `Contents/MacOS/ffmpeg` / `ffprobe`**——本脚本已按正确顺序处理，别用 `--deep` 一把梭后改动嵌套文件 |
| `The executable does not have the hardened runtime enabled` | 漏了 `--options runtime` |
| `has a code signature but it is not timestamped` | 漏了 `--timestamp` |
| Info.plist 相关 | 缺 `CFBundleVersion` 等，本模板已含 |

### 7.4 可选：universal2（Intel + Apple Silicon）

默认 CI（`macos-14`）只出 arm64。若要覆盖 Intel 用户：
```bash
rustup target add x86_64-apple-darwin
cargo build --release --target x86_64-apple-darwin
cargo build --release --target aarch64-apple-darwin
lipo -create \
  target/x86_64-apple-darwin/release/vidly \
  target/aarch64-apple-darwin/release/vidly \
  -output target/release/vidly
# ffmpeg 同理：两台 runner 各跑一次 build-ffmpeg-min.sh，lipo 合并后再打包
```
建议首版只出 arm64（现在 Mac 用户绝大多数已是 Apple Silicon），有反馈再补 universal。

## 8. Linux：deb 安装包

### 8.1 先做一处小代码适配（重要）

deb 规范不允许我们把私有 ffmpeg 放进 `/usr/bin`（会和系统 ffmpeg 冲突），正确位置是 `/usr/lib/vidly/`。因此在 **convert.rs 的 `find_binary()`** 中，exe 同目录检查之后追加一段：
```rust
// deb 安装布局：主程序在 /usr/bin，ffmpeg 在 /usr/lib/vidly
if let Ok(exe) = std::env::current_exe() {
    if let (Some(bin), Some(usr)) = (exe.parent(), exe.parent().and_then(|p| p.parent())) {
        let candidate = usr.join("lib/vidly").join(&name);
        if candidate.is_file() {
            return Some(candidate);
        }
    }
}
```
探测优先级变为：**exe 同目录 → deb 安装目录 → PATH → Homebrew 等常见目录**，各平台行为不变。

### 8.2 rfd 后端选择

deb 场景建议用 XDG Portal 后端，避免拖进整套 GTK 依赖：
```toml
rfd = { version = "0.15", default-features = false, features = ["tokio", "xdg-portal"] }
```
> 保留 GTK 后端也可行，此时 `Depends` 需加 `libgtk-3-0`，脚本里的依赖表同步改。

### 8.3 scripts/package-deb.sh（全文）

```bash
#!/usr/bin/env bash
# 用法：./scripts/package-deb.sh <version> <arch>
# 前置：target/release/vidly 与 out/bin/{ffmpeg,ffprobe} 已就绪
set -euo pipefail
VER="${1:?usage: package-deb.sh <version> <arch>}"
ARCH="${2:-amd64}"
ROOT="package/vidly"
rm -rf "$ROOT"
mkdir -p "$ROOT"/{DEBIAN,usr/bin,usr/lib/vidly,usr/share/applications,usr/share/icons/hicolor/256x256/apps,usr/share/doc/vidly}
# ── 主程序与 ffmpeg ──────────────────────────────────────────────
cp target/release/vidly                       "$ROOT/usr/bin/"
cp out/bin/ffmpeg out/bin/ffprobe              "$ROOT/usr/lib/vidly/"
chmod 755 "$ROOT/usr/bin/vidly" "$ROOT/usr/lib/vidly/"*
# ── control ──────────────────────────────────────────────────────
# 依赖可用 ldd 自动核对：ldd target/release/vidly | awk '/=> \//{print $3}' | xargs -n1 basename | sort -u
cat > "$ROOT/DEBIAN/control" <<EOF
Package: vidly
Version: ${VER}
Section: video
Priority: optional
Architecture: ${ARCH}
Depends: libxkbcommon0, libwayland-client0, libxkbcommon-x11-0, libx11-6, libglib2.0-0, libvulkan1, libegl1, libgl1, xdg-desktop-portal
Maintainer: Your Name <you@example.com>
Homepage: https://github.com/you/vidly
Description: Lossless MP4/MOV container converter
 GUI tool that converts between MP4 and MOV without re-encoding
 (lossless remux), powered by FFmpeg (LGPL build).
EOF
# ── 桌面入口 ─────────────────────────────────────────────────────
cat > "$ROOT/usr/share/applications/vidly.desktop" <<EOF
[Desktop Entry]
Type=Application
Name=Vidly
Comment=Lossless MP4/MOV remuxer
Exec=vidly
Icon=vidly
Categories=AudioVideo;Utility;
Terminal=false
EOF
cp assets/vidly-256.png "$ROOT/usr/share/icons/hicolor/256x256/apps/vidly.png"
# ── 文档与许可（LGPL 合规落点）──────────────────────────────────
cp out/bin/LICENSE-ffmpeg.txt "$ROOT/usr/share/doc/vidly/LICENSE-ffmpeg.txt"   # LGPL v2.1+ 文本
cat > "$ROOT/usr/share/doc/vidly/copyright" <<EOF
vidly ${VER}
Copyright (c) 2026 Your Name
License: MIT (see https://github.com/you/vidly)
This package bundles FFmpeg (in /usr/lib/vidly/), licensed under the
GNU LGPL (see LICENSE-ffmpeg.txt). FFmpeg source: https://ffmpeg.org/releases/
Users may replace the bundled ffmpeg binaries at that path.
EOF
# ── 打包 ─────────────────────────────────────────────────────────
mkdir -p dist
dpkg-deb --build --root-owner-group "$ROOT" "dist/vidly_${VER}_${ARCH}.deb"
echo "✅ dist/vidly_${VER}_${ARCH}.deb"
```

## 9. GitHub Actions 完整流水线

`.github/workflows/release.yml`——**打 tag（`v*`）即自动完成三平台构建、签名、公证、发布**：
```yaml
name: Release
on:
  push:
    tags: ["v*"]
  workflow_dispatch:     # 允许手动跑（此时不上传 Release）
permissions:
  contents: write
jobs:
  # ══════════════════════ Windows ══════════════════════
  windows:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: 版本号（Cargo.toml 为唯一来源）
        shell: bash
        run: |
          VER=$(grep -m1 '^version' Cargo.toml | sed 's/.*"\(.*\)".*/\1/')
          echo "VER=$VER" >> "$GITHUB_ENV"
      - run: cargo build --release
      - name: 安装 MSYS2 工具链
        uses: msys2/setup-msys2@v2
        with:
          msystem: MINGW64
          update: false
          install: >-
            mingw-w64-x86_64-gcc
            make
            nasm
            xz
      - name: 构建极简 LGPL ffmpeg
        shell: msys2 {0}
        run: ./scripts/build-ffmpeg-min.sh
      - name: 组装 dist/
        shell: bash
        run: |
          mkdir -p dist
          cp out/bin/ffmpeg.exe  dist/
          cp out/bin/ffprobe.exe dist/
          cp out/bin/LICENSE-ffmpeg.txt dist/LICENSE-ffmpeg.txt
          cp target/release/vidly.exe dist/
          # 待签名工件打包
          (cd dist && 7z a ../unsigned.zip vidly.exe ffmpeg.exe ffprobe.exe)
      # ── SignPath 第一段：签应用文件 ─────────────────────────────
      # ⚠️ input/output 参数名以 SignPath 官方 action README 为准
      - name: SignPath 签名（应用文件）
        if: ${{ secrets.SIGNPATH_API_TOKEN != '' }}
        uses: SignPath/github-action-signpath-action@v1
        with:
          api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
          organization-id: ${{ secrets.SIGNPATH_ORG_ID }}
          project-slug: vidly
          signing-policy-slug: release-signing
          input-artifact-path: unsigned.zip
          output-artifact-path: signed.zip
      - name: 解包签名结果回 dist/
        if: ${{ secrets.SIGNPATH_API_TOKEN != '' }}
        shell: bash
        run: 7z x signed.zip -odist -y
      - name: Inno Setup 打安装包
        shell: cmd
        run: |
          choco install innosetup -y --no-progress || exit /b 0
          "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DVersion=%VER% installer.iss
      # ── SignPath 第二段：签安装包 ───────────────────────────────
      - name: SignPath 签名（安装包）
        if: ${{ secrets.SIGNPATH_API_TOKEN != '' }}
        uses: SignPath/github-action-signpath-action@v1
        with:
          api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
          organization-id: ${{ secrets.SIGNPATH_ORG_ID }}
          project-slug: vidly
          signing-policy-slug: release-signing
          input-artifact-path: Output/Vidly-Setup-${{ env.VER }}.exe
          output-artifact-path: Vidly-Setup-${{ env.VER }}.exe
      - name: 收集产物
        shell: bash
        run: |
          mkdir -p artifacts
          if [ -f Vidly-Setup-${VER}.exe ]; then cp Vidly-Setup-${VER}.exe artifacts/
          else cp "Output/Vidly-Setup-${VER}.exe" artifacts/; fi   # 未配签名时的兜底
      - uses: actions/upload-artifact@v4
        with: { name: windows, path: artifacts/ }
  # ══════════════════════ macOS ══════════════════════
  macos:
    runs-on: macos-14            # Apple Silicon
    env:
      MACOS_SIGN_IDENTITY: ${{ secrets.MACOS_SIGN_IDENTITY }}
      APPLE_API_KEY_ID: ${{ secrets.APPLE_API_KEY_ID }}
      APPLE_API_ISSUER: ${{ secrets.APPLE_API_ISSUER }}
      APPLE_API_KEY_B64: ${{ secrets.APPLE_API_KEY_B64 }}

      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: 版本号
        run: |
          VER=$(grep -m1 '^version' Cargo.toml | sed 's/.*"\(.*\)".*/\1/')

      - name: 构建 LGPL ffmpeg（极简）
        run: |
          brew install nasm 2>/dev/null || true
          ./scripts/build-ffmpeg-min.sh
      - run: cargo build --release

          echo -n "$MACOS_P12_B64" | base64 --decode > cert.p12
          security create-keychain -p temp build.keychain
          security default-keychain -s build.keychain
          security unlock-keychain -p temp build.keychain
          security import cert.p12 -k build.keychain \
            -P "$MACOS_P12_PASSWORD" -T /usr/bin/codesign
          security set-key-partition-list -S apple-tool:,apple: -k temp build.keychain
      - run: chmod +x scripts/package-macos.sh && ./scripts/package-macos.sh "$VER"
      - name: 收集产物
        run: |
          mkdir -p artifacts
          cp dist/Vidly-${VER}.dmg artifacts/

        with: { name: macos, path: artifacts/ }
  # ══════════════════════ Linux ══════════════════════

    runs-on: ubuntu-22.04        # 用 22.04 保 glibc 兼容面

      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable

      - name: 上传合规文件

          gh release upload "$GITHUB_REF_NAME" LICENSE THIRD_PARTY.md --clobber
        env:
          GH_TOKEN: ${{ github.token }}
```

## 11. FAQ

**Q1：签了名还是弹 SmartScreen？**
SignPath 免费提供的是标准证书，SmartScreen 信誉按“证书+文件”积累，下载量上去后（通常数周）警告会消失。EV 证书才能即签即过，但无免费渠道。
**Q2：公证报 "bundle format not recognized"？**
公证对象必须是 dmg/zip，不能直接是 `.app` 目录。脚本中已先做 dmg 再公证。
**Q3：deb 装完启动提示找不到 ffmpeg？**
确认第 8.1 节的 `find_binary()` patch 已合入，且包内 `/usr/lib/vidly/ffmpeg` 存在（`dpkg -L vidly` 核对）。
**Q4：老版本 Ubuntu（20.04）装不上/装上跑不了？**
glibc 过旧。要么在 20.04 容器中构建，要么接受 22.04+ 支持范围并在 README 说明（推荐后者，20.04 已于 2025 年停止标准支持）。
**Q5：升级 ffmpeg 版本要注意什么？**
① 改 `scripts/build-ffmpeg-min.sh` 里的 `FFMPEG_VER`；② 三平台始终为自建 LGPL v2.1+，如上游 `COPYING.LGPLv2.1` 有变动则同步仓库根 `LICENSE-ffmpeg.txt`；③ 更新关于页中的源码链接版本。
**Q6：想闭源商业化怎么办？**
许可证章节的结论全部要重新评估：ffmpeg 换成你自编译的 LGPL 版仍可行（义务同 2.2），但 rfd 的 MPL-2.0 要求提供其源码途径；SignPath 免费签名也会失效（仅限开源），需购买商业证书。本项目已定 MIT 开源，此问仅作备忘。
